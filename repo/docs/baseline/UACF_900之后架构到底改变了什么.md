# 900 个来源之后，UACF 到底改变了什么

## 当前阅读说明 · 2026-10-08

本项目已公开发布，Apache-2.0由所有者选择。当前正文按发布结果修订；旧现场补记移入末尾历史附录，不能当成当前待办。源码与干净安装各197测试通过。新100的完整公开正文处理、约10%正文宿主复核和候选发布完成；100份加入共享链，21份已有宿主分类回填，79份继续待共享语义分类。旧900全量语义审查、附件/领域真值、任意工具控制和所有宿主现场自动回调未宣称通过。完整阅读入口见《UACF_阅读导航》，冻结状态见Release与VERIFICATION。

2026-10-07｜面向普通使用者的能力说明｜来源整理、软件行为与尚未验证的效果分别说明。

UACF 现在可以把过去做过的工作变成下一次工作的准备材料，也可以在它管理的交付入口检查某些明确的遗漏。它并没有因为读过 900 个来源，就变成一个不会再犯错的模型。改变发生在任务、来源、经验、执行入口和验收之间的连接上。

## 先回答：总说明做了没有

已经有《正式完整版设计总说明》《第二阶段整体运行与操作模式》《第一阶段设计补充04》《从早期工作台到当前流程的迭代说明》，另有完整的中文和英文普通用户手册。本轮另补完整英文设计总说明。旧第一阶段总览及补充01—03保留；这些文件分别承担总设计、操作、差异和迭代历史的职责。

文档齐全和系统验收完成是两回事。说明必须告诉你哪些操作真的起作用，哪些只生成了代码，哪些现场连接还有缺口。后续版本改变时，不能沿用旧版测试结果宣称新版全部通过。

## 1. 它能从以前的工作中找出对当前工作有用的经验

例如，你明确要求一种语言，却得到另一种语言的首答。下一项相似工作可以收到“先核对要求的语言、适用范围和排除条件”这个原则。科研中的数值，则要区分实测数据、文献引用和示意估计；没有原始曲线或运行记录，不能把示意表写成实测结果。

这不是把旧聊天整段塞给模型。系统先按当前任务找少量候选，保留真实来源；必要时才展开一个病例的条件。当前公共指导最多3条、合计4000字节。检索命中只是准备，真正送达须有调用回执，实际采用须能在输出或操作中看到对应行为。没有这些证据时，界面应保留“未知”，不能显示“已使用”。

## 2. 相似错误可以共用一个原则，但不同条件不能被抹掉

两个不同说法的语言遗漏，可能是同一原则的实例。端口冲突也可能共用“先确认占用者身份”的原则，但自己拥有的进程、别人正在使用的进程、可以改端口的项目，处理分支不同。出现同样的报错文字，甚至来自同一模板，也可能是不同的问题。

因此，系统分别保留等价、条件分支、独立问题和证据不足。旧实例链接原则，而不是复制一千份规则。文字相似度和检索分数只帮助找到需要比较的候选；hash只证明文件或修订身份一致。两者都不替代语义判断。

900来源目前生成3793知识候选、1980问题或边界实例。已有151对审查涉及115实例，另1865实例没有这种审查。727相关和274条件扩展标签不能解释成“已经确认合并”。这些数量描述准备工作，不能推断独立错误有多少，也不能证明错误已经饱和。

## 3. 某些问题已经从一句提醒变成有限的检查关口

目前有五类注册检查：

| 你遇到的行为 | 系统可以检查什么 | 检查范围 |
|---|---|---|
| 引用一个来源实际没有的话 | 声称的逐字引文是否存在 | 已提交的来源绑定候选；不验证领域事实 |
| 没有验收就交付“完成” | 当前任务修订和环境有没有注册通过结果 | UACF管理的交付入口 |
| 修复新问题时破坏已有结果 | 预声明受保护文件有没有变化 | 指定路径和登记边界 |
| 付费调用结果不明就再发一次 | 是否存在未知、预留或已派发回执 | 共享派发器；不覆盖任意外部调用 |
| 漏掉用户最重要的一项工作 | 每个显式必需工序有没有当前验收 | 已声明的逐工序交付合同 |

例如，合同规定完成说明、前台验证和真实闭环，只有说明文件和测试通过，交付门控仍应拒绝接受。这里的拒绝针对注册入口；不能声称它会拦住任意Codex工具，或看见模型的私有思考。普通聊天里未经接线的“完成”文字，也不自动等于规范验收。

五个关口是已实现的有限执行合同。部分来自900整理揭示的问题，逐工序防遗漏还受到本次用户纠正推动。不能把全部历史工程成果都归因于900，也不能说1980实例变成了1980条硬规则。

## 4. “失败几次就强制回去读结构”现在有没有

旧v7—v7.4的DSH治理包已有同实验/同失败计数与真实工具入口停止。之前未查旧包便忽略这段实现，是历史解释错误。当前UACF本次另补有限注册read-probe的计数、停止与实际结构/命令重准备；这不代表任意宿主工具都有“失败三次便强制阅读全部结构”的通用门控。已有的相近控制是：来源或任务修订变化后，旧依赖和旧验收不能直接继承；已知失败或未知回执不能靠盲目重试掩盖；必需步骤缺失不能在注册入口交付。

本次有限入口已经声明读取目标与次数上限，并实际完成停止、结构回读与恢复测试。将这种控制扩展到其他工作类型时，仍须逐类定义失败、必要结构和恢复证据，再接入真实入口；不能把本次文件读取测试称为任意宿主工具已经受控。

## 5. 不必等项目永远结束，才能整理

重要纠正、明确要求整理、实质需求变化、阶段成果和用户明确满意或结束，都可以形成整理节点。几句短补充合并，日常小事轻量处理，情绪本身不证明AI出错。触发判断只用当前公开节点的结构信号，提示依据上限1024字节，不另外开启模型推理。

普通信号累计3次才准备增量整理；普通捕获间隔至少15分钟；明确请求或严重纠正可立即准备。周期扫描对明确启用该模式的本地任务检查元数据，7天闲置或24小时未检查时检查是否遗漏。它不代表已经连接并监控整个ChatGPT账号，也不自动收费重读闲置对话。

“需要整理”的判断、“真实公开来源到达”、“候选生成”、“条件比较”和“回填完成”是不同环节。原生hook接线、公开接口回读和手工标注分别记录；回读真实结束状态可以证明过去的结束，不能冒充当时实时回调成功。全部自动结束回填的现场缺口仍要实测。

## 6. 私人经验可以保留本机链接，也可以分享脱敏版本

本机层保存真实来源、修订、原条件和判断依据。可分享层只保留抽象原则、适用/排除条件、合成正反例和限制。例如公开分享“先核对输出语言”，不分享你的私人邮件、联系人、具体项目或聊天地址。

旧候选可以直接制作公开投影，不需要再花钱重提取900。投影修改后，原复核失效；同名原则必须明确修订，不自动覆盖。收到别人分享的模块，也应先导入待审草稿，检查许可及条件，再允许进入本地任务上下文。导入一个原则不会自动安装一条执行规则。

当前三个真实旧病例派生模块展示了这条路径：必需工作、要求语言、端口占用者身份。三个模块不代表全部900已经完成脱敏。秘密扫描也不能保证语义上完全无隐私，因此公开发布仍要核对具体文件和模块范围。

## 7. 对科研、写作、视频和普通工作有什么意义

科研工作可以保留“数据从哪里来、是否实际验证、哪些附件未读”的区别；写作可以保留语言、格式与用户本轮修改；视频工程可以链接素材和已完成步骤；简单日常工作不必每句话都启动复杂整理。

它的价值是减少遗漏、把同一原则用在适当条件下、保留可核对的进展，而不是逼所有人学习Git命令。用户通过常设前台建立任务、查看经验和来源、处理待审、确认结束。压缩包提供启动入口和中英文手册，宿主安装助手只负责配置接线，宿主是否真的加载仍应另看回执。

新增100用于验证这些路径是否实际工作，不用于凑更大的数字。预算上限20元已经授权；仍应先通过闭环，按10、30、60、100检查。任何来源、结束事件、回填或费用对不上，都应停止后续新增、保留回执并修复。




## 2026-10-08 命令连续性与人可读意见修正

当前Task增加独立命令通道。每条保存原话引用、当前宿主解释、来源修订、行动/讨论/引用/重复/未决类别和完成证据；补充默认追加，变更旧要求必须明确订正，保留旧修订。语音订正、修辞及AI拟文由当前宿主定点判断；词法检查与hash不能完成这些语义解释。准备上下文时有效命令全部进入mandatory lane，超过上限明确overflow，不让可选知识挤掉旧要求。宿主压缩后须再次调用当前Task上下文；没有真实hook回执不声称已强制所有桌面回合自动调用。

注册交付先检查尚未完成的有效命令，再检查原注册Validation。有限read-probe入口持久记录同实验次数，达到约定上限停止，guard_reprepare实际回读声明结构与当前命令并要求新的修正依据后恢复；不以hash证明读懂内容，不拦截任意私有思考/宿主工具。旧v7.4治理有自己的真实DSH工具拦截，本次保留历史并另验当前接线。

前台“历史经验给当前工作什么建议”直接显示一份已审原则及其多个实例链接，展开可看条件差异、依据与原实例。独立和证据不足不并入该原则，未经审查的知识/问题继续逐项查询，不按粗机制族或文字相似度自动去重。原候选与全部历史保留。完整项目历史已重新依据早期工程包和阶段实现按日/阶段重写。
