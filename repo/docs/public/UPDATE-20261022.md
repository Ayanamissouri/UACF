# UACF update — 2026-10-22: task integrity and cross-host continuity

This is an incremental public update following [`phase2-2026-10-21-governance.1`](https://github.com/Ayanamissouri/UACF/releases/tag/phase2-2026-10-21-governance.1). It preserves the published repository history, earlier releases, Apache-2.0 notice and public packaging rules.

## What changed in this release

- New work created through the default Host entry now requires an explicit command contract. Implementation, review and delivery stages check that active requirements were registered; delivery also rechecks that linked result evidence is current. Reconfiguration preserves the prior stage plan for review. Existing archived Tasks are not rewritten or reclassified.
- A compact work brief is derived from the canonical Task and exposes open requirements, output ownership, readiness and next action. The optional workspace view uses compare-and-swap and preserves prior views; it does not become a second source of task state.
- Capability observations now distinguish generated, installed, loaded, called and verified states, with machine, Host version, profile, source identity and session scope. A record cannot authorize a tool or promote itself to verified.
- Optional recall removes exact duplicates while preserving distinct sources, conditions and corrections. It adds short source-bound hints without adding model calls or changing the canonical asset store.
- Codex/Pi MCP and the existing DSH context path expose the current brief and capability observations through each Host's available interface. Pi can read `/uacf-brief`, and uncertain action timeouts are reconciled by reading the original operation rather than resending it.
- The shared `uacf-continuity` Skill now points to conditional references for task closure, Host differences and root-cause work. It remains guidance; enforcement depends on each actually loaded Host integration.

## Change from the previous public release

The 2026-10-21.1 release added default-host admission, unified cross-source retrieval, adaptive checkpoints, command and learning contracts, metric-evidence checks and portable CI. This update tightens the command contract at stage entry and delivery, exposes canonical-derived recovery information, records Host capability evidence by scope, and protects distinct retrieval cases from being hidden by a shared principle label.

No MemOS backend, external workflow controller, new runtime dependency or model request was added. This is a source/package release: it does not update an already running installation. It does not move, rewrite or reprocess historical archives.

## Verification

The full public candidate suite passed **245 tests**. The organizing-upgrade and related command-ledger, stage workflow, Host admission, learning, storage-preservation, verifier and transport subset passed **71 focused tests**; the Pi timeout reconciliation contract and selected Node syntax checks passed as well. The test claims cover finite implementation behavior and preservation checks; they do not establish that natural-language interpretation errors are solved, that every Host hook fires in every session, or that domain conclusions are true. See [current verification](VERIFICATION.md) for the measured scope.

Existing immutable archive records were checked by the local registered verifier before this public export. Those private machine receipts and source locators are intentionally not part of this public release. This package contains source, synthetic tests and reviewed documentation only; no user database, raw chats, runtime logs, credentials, local paths, private Git history, `node_modules`, virtual environment or third-party runtime binaries are included.

## Upgrade

Download `UACF-2026.10.22.zip` and `SHA256SUMS-r1`, verify the checksum, extract into a new directory and follow the included operations guide. Keep existing data and credentials outside the release tree. GitHub publication does not switch the local running service.
