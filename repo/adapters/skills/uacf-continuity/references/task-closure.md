# Keep the requested outcome visible

Interpret the current user request with its supplements before changing the system. Preserve earlier requirements unless the current user cancels or corrects them. Record actionable requirements with their original quoted basis; current user instructions and historical examples are different sources of authority.

Use the canonical Task as the only work state. `uacf_work_brief` / the `work_brief` action reads open requirements, the output contract and registered checks. `work_view_refresh` may create a disposable `views/current-task.json` under the allocated project work directory. It is a recovery view, not an editable second plan. Re-read after compression, revision changes and important corrections; do not replay old actions.

For each requested outcome, locate the actual result and appropriate evidence. A command exiting successfully, a file hash matching, or a stage marked completed establishes only that narrow fact. Architecture requests require an actual explanation and decisions; code changes require relevant behavior checks. Review scope and meaning separately from mechanical validation, and identify who made the semantic judgment.

Finish with a direct answer, the usable result, how it was verified, and material remaining work. Keep implementation notes subordinate to what changed for the user. A missing component remains explicit; do not silently omit it to make delivery look complete.

Use proportionate coordination and checks. A small document correction does not justify all archive tests or a team of agents. If delegation is authorized and useful, define the write scope, input, output, budget and evidence; one active writer owns a given write scope. Existing authorization persists.

Methods informed by Superpowers completion/planning guidance and PROVE's proportionate coordination. Local wording and behavior are adapted to UACF; no upstream controller or automatic delegation is installed.
